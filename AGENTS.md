# Streamcut — инструкции для работы в репозитории

Перед изменением прочитайте [README](README.md), [разделение задач](docs/WORKSTREAMS.md) и актуальный GitHub Issue. Сначала проверьте `git status --short` и выполните `git fetch origin`. В начале работы создайте свою ветку от `origin/main`. В разных чатах используйте разные клоны или worktree.

- Используйте только ветку своего задания, `codex-a/*` или `codex-b/*`. Не работайте в одном worktree параллельно. Без явного решения владельца не изменяйте чужую ветку, не пушьте напрямую в `main`, не делайте force push или merge.
- Если рабочая ветка уже разошлась с `main`, сначала прочитайте изменения и найдите пересечения. Локальную неопубликованную ветку можно перебазировать. Опубликованную ветку синхронизируйте обычным merge из `origin/main`, чтобы не переписывать историю.
- Координируйте перекрытие файлов через Issue или PR. Предложение менять соседний контракт сначала опишите в PR. Сохраняйте обратную совместимость существующей очереди, SQLite и пользовательских настроек.
- Каждый пуш должен состоять из осмысленных коммитов. В сообщении обязательны однострочная тема, пустая строка и тело с разделами «Что изменилось», «Почему», «Проверки». Если проверка не выполнена, укажите причину. Опишите миграции, ограничения и новые переменные окружения, когда они влияют на запуск.
- В PR укажите номер задачи, поведение до/после, результаты проверки и заметки для другого чата. Сохраняйте контекст будущей работы в GitHub и `docs/WORKSTREAMS.md`, без копирования приватных переписок.
- Публичный репозиторий не хранит токены API, персональные данные, SQLite, исходные записи, приватный манифест хостинга, SSH-ключи и адреса реальной инфраструктуры. Для тестов используйте синтетические файлы и ответы API. Перед пушем просмотрите staged diff и список файлов.
- Работа с аккаунтами только через официальные API с авторизацией владельца. Не включайте реальные загрузки в тесты и не подстраивайте выход для обхода ограничений площадок. При сбое маршрута или неясном результате отправки сохраняйте существующие защитные состояния.
- Форматы роликов, маршруты RU / EN / ESP и часовые пояса закреплены в README. Язык, рынок и страна выхода — разные поля. Прямой маршрут не устанавливает целевую страну.

После открытия PR GitHub Actions проверяет проект и метаданные коммитов. Порядок передачи проверки и обновлений — в [docs/CODEX_REVIEW.md](docs/CODEX_REVIEW.md). Используйте публичный адрес GitHub noreply для автора и коммитера.

Для изменений сервера запускайте `(cd control-room && python3 -m unittest discover -q)`. Для интерфейса — `(cd control-room && npm test && npm run check)`. Для монтажа — `python3 -m unittest discover -q` из корня. Для манифестов — `kubectl kustomize control-room/deploy`, если доступен kubectl. Для сквозной проверки используйте тестовый файл и отдельную временную папку данных.
