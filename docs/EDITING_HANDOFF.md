# Streamcut — передача работы над поиском и монтажом

Текущая цель владельца: надёжно находить авторов, эфиры и записи YouTube/Twitch на русском, английском и испанском, отбирать интересные моменты по смыслу и готовить готовый MP4 для просмотра. Поддержать и автоматический поиск, и ручной вход «ссылка + расшифровка». На этом этапе ничего не отправлять в соцсети.

## Что уже сделано

- **Конвейер:** есть Python/SQLite, фоновый поиск и локальный монтаж, входящие папки, загрузка файла из браузера, карточки источников и очередь. Для клипов сохраняются MP4, SRT/ASS, манифест и тексты.
- **Монтаж:** `clips.py` ищет пики звука и движения или получает ручную метку. `editing.py` кадрирует и собирает `split`. Первая треть кадра — веб-камера автора, снизу — геймплей или видео, на которое он реагирует. `captions.py` рисует описание из 3–5 слов по стыку зон. Субтитры расположены ниже, по центру кадра, на высоте 72%. Варианты оформления включают белый текст и лаймовую подсветку слова. Стиль уже согласован.
- **Оригинальная речь:** SRT с таймкодами исходника можно передать напрямую. Без SRT путь распознавания использует faster-whisper, если он установлен. Звуковая дорожка берётся из выбранного отрезка записи. FFmpeg кодирует её в AAC, сохраняя содержание и синхронизацию. Диктор, дубляж и замена звука здесь не нужны.
- **Поиск:** в [PR #4](https://github.com/nuclear4ik/gta-stream-clips/pull/4) — 10 стартовых имён на рынок и обновляемый топ до 10 по свежим просмотрам и аудитории текущих эфиров. Каждый цикл раз в пять часов. Поиск выходит за пределы списка, учитывает имя автора в заголовке перезалива и связывает Twitch-эфир с записью по `stream_id` после перезапуска. Если живых данных мало, список не дополняется выдуманными авторами. Правки и тесты из [PR #3](https://github.com/nuclear4ik/gta-stream-clips/pull/3) применены в #4 обновлённым коммитом.
- **Связь метаданных с файлом:** в #4 запись ждёт разрешённый исходник. Файл `youtube-<id>.mp4`, `twitch-vod-<id>.mp4` или `twitch-stream-<id>.mp4` во входящей папке нужного языка автоматически связывается с найденной ссылкой. Файл, появившийся раньше метаданных, ждёт совпадения. Старые автоматические кандидаты освобождают место. Ручные источники сохраняются.
- **Исправление реакции:** [PR #5](https://github.com/nuclear4ik/gta-stream-clips/pull/5) убирает ошибку, когда фоновый монтаж вместо `split` принудительно использовал `crop`. Запись по ссылке ждёт измеренных границ камеры. Профиль `stream.reaction.json` рядом с `stream.mp4` принимает `facecam`, `headline` и необязательные `gameplay` и точки фокуса. Рядом можно положить `stream.srt`. После появления профиля монтаж возобновляется. Фрагмент без исходного аудио или субтитров в режиме реакции отбрасывается.
- **Инфраструктура:** панель с разделами «Очередь», «Источники», «Аккаунты», «Подключения», расписание Москва/Нью-Йорк/Мадрид, Docker и Kubernetes-манифесты, GitHub Actions и правила двух чатов. Подготовлена приватная отправка YouTube после OAuth. Для Instagram и TikTok доступен экспорт MP4. Всё это вторично до приёмки монтажа.

## Что проверено и что осталось

Тесты PR #4, включая GitHub Actions, прошли. Локальный сквозной прогон на тестовых ответах YouTube/Twitch связал файлы по ID, смонтировал по одному MP4 1080×1920 и добавил в очереди RU, EN и ESP. Отдельный сквозной тест PR #5 проверил ожидание профиля, две области кадра, описание на высоте 634 px, центр субтитров на высоте 1382 px и сохранение исходного звукового сигнала. В последней локальной панели применяется исправление #5, но её старая рабочая папка не равна полной версии GitHub с динамическим поиском.

Ключей YouTube и Twitch для живого прогона на рабочем хосте не было. Реальная выгрузка не выполнялась. Чистых записей с веб-камерой реального автора в папке не было. Старый `demo.mp4` — рисованный ролик с уже встроенным текстом. Были сделаны три черновика на официальных кадрах Rockstar с синтезированной озвучкой. Владелец этот формат отклонил. Не использовать их как ориентир монтажа или как доказательство работы со стримерским исходником.

## Следующая задача — довести от источника до MP4

1. **Живой поиск.** Подключить официальные API через окружение хоста. Проверить отдельно свежий ролик YouTube, текущий Twitch-эфир и запись Twitch. Проверить циклы, дубли, смену состава топа и возобновление после перезапуска. На сбоях сохранять последнюю пригодную выдачу и показывать ошибку источника. Поиск метаданных сам по себе не выдаёт файл.
2. **Доступ к записи.** Поддержать два входа: локальный/предоставленный владельцем файл и автоматическую передачу из явно разрешённого источника, например своей записи эфира или авторского хранилища. Закрывать этап только после проверки наличия медиа. Для текущего эфира видео появляется после готовности предоставленного фрагмента или VOD. Официальные API поиска не обеспечивают скачивание чужих VOD. Если есть лишь ссылка, статус «Нужен исходный файл» сохраняется. Не обходить ограничения платформ. Проверить дедуп и не повторять монтаж того же исходника.
3. **Расшифровка.** Принимать ручные ссылку и SRT/VTT либо JSON сегментов `start_seconds`, `end_seconds`, `text` с опциональными таймкодами слов. Без готовой расшифровки брать оригинальный звук и распознавать его. Текст без времени сначала синхронизировать с аудио. Хранить таймкод в координатах полной записи, выводить причину ошибки при несовпадении текста и файла.
4. **Отбор по смыслу.** Добавить анализ таймкодированной речи моделью с чёткой структурой ответа. Для каждого фрагмента нужны начало, конец, оценка, короткая причина выбора и описание из 3–5 слов на языке речи. Ищем ясную реакцию, интересный контекст и завершённую мысль. Не брать пустые места, рекламные вступления и выводы без контекста. Использовать текущие пики звука/движения как подсказки. Валидировать границы, длительность, совпадение с расшифровкой и перекрытия. При ответе модели с ошибками оставлять ручной режим и понятный статус.
5. **Точная нарезка.** Добавить монтаж по заданным `start_seconds` и `end_seconds` с общей шкалой для видео, звука и субтитров. Текущий `--at` выбирает окно вокруг отметки и не означает точный старт. Ручные интервалы должны работать без модели. Поддержать сопоставление профиля веб-камеры с исходником. Не угадывать область камеры, если раскладка неизвестна или меняется. Следующий удобный шаг — отмечать камеру и видео на кадре с предпросмотром.
6. **Просмотр.** Показывать причину выбора, исходный таймкод и готовый MP4. Разрешить скорректировать границы, заголовок и кадрирование, затем перерендерить. Для MVP боковые эффекты ограничить локальными файлами и очередь держать в режиме проверки. Оставить отправку выключенной даже при наличии аккаунтов.

Минимальный критерий готовности: реальная разрешённая запись с веб-камерой проходит от найденной или вручную внесённой ссылки до готового ролика. На втором исходнике проверяются ручная расшифровка и точные границы. На третьем языке проверяется, что заголовок и субтитры следуют речи. Сравнить звук с выбранным диапазоном исходника, проверить двухзонный кадр и синхронизацию нескольких слов вручную. Тесты и локальный просмотр обязательны до разговоров о публикации.
