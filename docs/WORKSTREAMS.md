# Работа двух чатов

Каждый поток ведётся в отдельной ветке от `origin/main` и отправляется в отдельный PR. Чаты обмениваются изменениями через GitHub, а не через скопированные файлы. Если у второго чата другой GitHub-аккаунт без права записи, он может открыть PR из своего fork.

## Поток A — подключение и первый пилот

**Ответственный — текущий чат.** Ветка `codex-a/platform-pilot`, [задача #1](https://github.com/nuclear4ik/gta-stream-clips/issues/1).

- Подтвердить прямой HTTPS-маршрут, отдельно проверить уровень OAuth и правильность ID канала.
- Пройти один приватный тест YouTube после авторизации владельца. Зафиксировать, где смотреть подтверждённый результат и последний отчёт Analytics.
- Подготовить пилот развёртывания на существующем сервере. Обновить короткую инструкцию владельцу для YouTube, Instagram и TikTok.
- Основные файлы: `control-room/transport.py`, `control-room/connections.py`, `control-room/metrics.py`, `control-room/deploy/`, `ACCOUNT_SETUP.md`. Координация с потоком B обязательна при изменении `studio.py`.

Результат — понятный порядок подключения одного собственного канала и отчёт о проверках. Реальные ключи, доступы и результаты без авторизации остаются ожидающими.

## Поток B — качество автопоиска

**Ответственный — второй чат Codex.** Ветка `codex-b/discovery-quality`, [задача #2](https://github.com/nuclear4ik/gta-stream-clips/issues/2).

- Улучшить независимую проверку темы GTA 6 и совпадения имени автора в названии ролика или канала. Проверить варианты написания и ложные совпадения по RU, EN и ESP.
- Проверить на обезличенных ответах официальных API: оригинальные публикации, перезалив с именем только в заголовке, стороннее упоминание, повторный результат, текущий Twitch эфир и его VOD.
- Уточнить документированные настройки списков авторов и объяснение причин отбора.
- Файлы: `control-room/discovery.py`, `control-room/CREATORS.md`, `control-room/test_discovery.py`. Изменения общего API, очереди, OAuth, маршрутов и хостинга идут отдельной задачей после сверки с потоком A.

Результат — тесты, правки поиска без скачивания медиа и PR со сводкой влияния на отбор.

## Синхронизация перед задачей и перед PR

```sh
git status --short
git fetch origin
git log --oneline --max-count=8 origin/main
git diff --stat origin/main...HEAD
```

Когда один PR вошёл в `main`, второй чат подтягивает `origin/main`, пересматривает пересечения и запускает затронутые проверки. После объединения обновляйте локальный `main` через `git pull --ff-only`. При конфликте изменения не выбрасываются и не заменяются версией одного чата вслепую.

Для перекрёстной проверки PR используйте [процедуру ревью](CODEX_REVIEW.md). Автоматические проверки проекта запускаются GitHub Actions.
