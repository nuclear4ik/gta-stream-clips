# Проверка изменений между двумя чатами

GitHub Actions запускает тесты на каждый новый PR и при обновлении его ветки. Проверки охватывают монтаж, поиск, сервер и панель. Также проверяются структура сообщения коммита и учётная запись автора: для публичной ветки используйте адрес GitHub `users.noreply.github.com`. Адреса ошибок не выводятся в журнал. В PR из нового форка GitHub может сначала запросить одобрение запуска проверки.

## Как передавать работу

1. Автор открывает PR с номером Issue, объяснением, результатом тестов и пунктом «Другому чату проверить…». Чат A ведёт подключение, очередь и развёртывание. Чат B ведёт источники и качество отбора. Результаты GitHub Actions видны во вкладке Checks.
2. На другом аккаунте Codex откройте PR. Сначала проверьте падения из GitHub Actions. Затем посмотрите diff, воспроизведите спорные случаи и дайте автору короткую задачу с одним ожидаемым результатом на каждый дефект. Если ответа от GitHub или API не было, пометьте путь как непроверенный.
3. Автор исправляет в своей ветке, описывает первопричину, добавляет проверку и обновляет PR. После следующего пуша GitHub Actions повторяет проверки. Не сливайте изменения при незакрытых замечаниях или без решения владельца.
4. Если замечание про другой компонент, создайте отдельный Issue со ссылкой на PR, ожидаемым поведением и проверкой. Не передавайте реальные токены, сетевые адреса, видео или содержимое рабочей базы.

Для взаимной автоматической проверки с моделями понадобится отдельная привязка события GitHub к каждому аккаунту Codex. В текущей конфигурации проверки GitHub запускаются автоматически. Второй аккаунт по-прежнему самостоятельно открывает PR и оставляет оценку.

## Готовые инструкции для проверяющего чата

> Проверь новый или обновлённый PR в https://github.com/nuclear4ik/gta-stream-clips от другого рабочего потока. Прочитай AGENTS.md, связанный Issue и результаты Checks. Укажи воспроизводимые дефекты с файлом, строкой и ожидаемым результатом. Особое внимание удели дублям, языку источника, перезапуску SQLite, ограничениям API и моменту фактической загрузки. Каждый дефект оставь как задачу в PR. Не меняй ветку автора и не сливай PR. Если замечаний нет, укажи, что проверено и какие реальные интеграции не тестировались.
