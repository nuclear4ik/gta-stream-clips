# Нарезка стримов GTA VI

Локальный инструмент на Python. `clips.py` подбирает фрагменты из записи, монтирует вертикальные MP4 для YouTube Shorts, TikTok и Instagram Reels и готовит тексты. `twitch_live.py` показывает, кто сейчас в эфире, в порядке числа зрителей. Поиск фрагментов и монтаж работают локально. Подойдёт видеофайл OBS или архив эфира, который можно использовать для нарезки.

Новое оформление смотрите в `previews/captions-neon.mp4` и `previews/captions-neon.jpg`. Это пример на неподвижном кадре из демо с вручную заданными словами и таймкодами, а не результат распознавания речи. Варианты `gold` и `clean` сохранены рядом как JPG.


## Вебкамера и геймплей в одном ролике

Нужны Python 3.10+ и FFmpeg с `ffprobe`, кодировщиком `libx264` и фильтром `ass` (libass), который рисует тему и субтитры. На Windows команда запуска Python может называться `py`, на macOS и Linux — `python3`. В распакованной папке выполните команду, подставив координаты вебкамеры в своём видео:

```bash
python3 clips.py "stream.mp4" --output "result" --facecam "74%,70%,25%,29%" --headline "Побег через мост" --hook tease --transcribe --language ru --burn-captions
```

`--facecam` принимает четыре числа. Это расстояние от левого края, расстояние от верхнего края, ширина и высота следующими друг за другом. Можно указать проценты или пиксели, например `--facecam "1420,756,480,313"` для записи 1920×1080. Снимок для измерения можно сохранить командой `ffmpeg -ss 00:02:00 -i "stream.mp4" -frames:v 1 frame.png`. Для одной и той же сцены OBS координаты подходят и для следующих записей.

Скрипт использует всю площадь кадра 9:16. Верхние 33% занимает вебкамера, нижние 67% — игра. Обе зоны идут от края до края. Короткая тема располагается на стыке, в одну или две строки. `--headline` задаёт её вручную. Без этого параметра скрипт ищет короткую реплику возле пика или подставляет `--topic`.

Скрипт выбирает крупнейший прямоугольник рядом с вебкамерой. Его можно переопределить через `--gameplay "x,y,ширина,высота"`. Чтобы заполнить нижнюю зону, края широкого исходника обрезаются. Если действие или HUD смещены, укажите точку внутри области через `--gameplay-focus "63%,50%"`. `--facecam-focus "50%,42%"` так же смещает кадр камеры. Координаты фокуса считаются внутри выбранной области исходника.

Субтитры располагаются **ниже центра зоны геймплея**, на 72% высоты кадра: X=540, Y=1382 на холсте 1080×1920. Это на 105 пикселей ниже предыдущего варианта. При экспорте 720×1280 координаты и оформление масштабируются. В макетах `fit` и `crop` используется та же высота 72%. Заголовок остаётся на стыке камеры и игры.

По умолчанию используется `--caption-style neon`: Montserrat ExtraBold, крупный белый текст прописными буквами, тёмная обводка, мягкая тень и лаймовое выделение произносимого слова. Доступны `--caption-style gold` с тёплым жёлтым акцентом и `--caption-style clean` без цветового выделения. Акцент появляется только при наличии таймкодов слов из распознавания; обычный SRT отображается белым.

`--caption-y 72` задаёт центр текста в процентах **всего кадра**; допустим диапазон 40–80. Без параметра используется высота 72%. Для двух строк остаётся запас снизу под свёрнутый интерфейс; это рабочий отступ, а не гарантия для всех версий приложений и раскрытых описаний. Нижняя часть и кнопки соцсетей могут перекрывать видео по-разному: перед публикацией проверяйте предпросмотр в приложении.

## Начало ролика

Скрипт учитывает движение в выбранной области вебкамеры наряду с громкостью и движением в игре. Пик выбирается по этим сигналам. Чтобы выбрать конкретную реакцию, задайте таймкод через `--at`.

| Режим | Что происходит |
|---|---|
| `--hook tease` | Вставляет фрагмент с пиком первым, затем показывает весь эпизод с начала, включая развязку. |
| `--hook move` | Переносит фрагмент с пиком в начало и стыкует оставшиеся части без повтора пика. |
| `--hook off` | Показывает эпизод по хронологии. Это режим по умолчанию. |

`--hook-seconds` задаёт длительность вставки от 0,8 до 3 секунд. По умолчанию это 1,6 секунды. Если пик уже в начале эпизода, хук пропускается. Режим `tease` увеличивает итоговую длительность клипа на длину вставки. Режим `move` сохраняет длительность. Видео, звук и субтитры используют одну последовательность таймкодов.

## Нарезка без раздельного макета

```bash
python3 clips.py "stream.mp4" --output "result" --count 3 --seconds 35 --creator "Имя стримера"
```

Для каждого отобранного момента появится папка `clip-01`, `clip-02` и так далее.

- `clip.mp4` — вертикальный ролик 1080×1920, 30 кадров/с, H.264 и AAC при наличии звука.
- `post.txt` — черновик заголовка и описания, а также короткий текст для X.
- `captions.srt` — субтитры с таймкодами готового ролика.
- `overlay.ass` — текст на стыке и встроенные субтитры в раздельном макете. В других макетах встроенные субтитры сохраняются как `captions.ass`.
- `fonts/` и `FONT-LICENSE.txt` — шрифт для воспроизводимого оформления ASS и его лицензия.
- `manifest.json` в общей папке — файлы, границы и порядок фрагментов, тексты, стиль и позиция субтитров на холсте 1080×1920.

Без `--facecam` в вертикальном ролике виден весь исходный кадр с полями. `--layout crop` заполняет кадр обрезкой по центру, `--width 720` экспортирует 720×1280. `--topic "GTA V"` меняет тему роликов. Через `--source-url` можно добавить ссылку на эфир для описания. Для каждого запуска нужен новый путь `--output`.

Скрипт анализирует громкость и изменение кадра каждые полсекунды, оставляет наиболее выраженные пики и пропускает фрагменты с существенным пересечением. В клип попадает примерно 40% времени до пика, если это позволяет исходная запись. Громкая музыка, заставки и переключения сцен тоже могут попасть в подборку. Для слабых сигналов уменьшите `--threshold` с 1.6 до, например, 1.1. Для конкретного момента используйте `--at` вместо автоматического поиска, при необходимости несколько раз:

```bash
python3 clips.py "stream.mp4" --output "manual" --at 12:40 --at 01:07:16 --seconds 30
```

## Субтитры и заголовки с цитатами

Если у вас есть готовый SRT в UTF‑8 с таймкодами **исходного видео**, можно обойтись без модели:

```bash
python3 clips.py "stream.mp4" --output "captioned" --srt "stream.srt" --burn-captions
```

Текст показывается группами до четырёх слов. Длинный текст переносится на две строки и при необходимости уменьшается, без удаления слов. При распознавании через faster-whisper текущее слово подсвечивается цветом выбранного стиля; размер и положение фразы при подсветке не меняются. Готовый SRT обычно содержит время целых фраз, поэтому фразы делятся пропорционально длине текста и показываются без подсветки отдельных слов.

Для автоматического распознавания установите `faster-whisper` для того же интерпретатора, которым запускаете скрипт:

```bash
python3 -m pip install faster-whisper
python3 clips.py "stream.mp4" --output "captioned" --transcribe --language ru --burn-captions
```

Модель `base` при первом использовании загружается автоматически. Чтобы работать офлайн, укажите распакованную локальную модель через `--model "/path/to/model"`. Модель запускается на CPU и получает только отобранные фрагменты. Без параметра `--language` язык определяется автоматически. Для субтитров используется Montserrat ExtraBold с кириллицей из `assets/fonts/`. Он загружается через FFmpeg `fontsdir`, устанавливать его в систему не нужно. Шрифт получен из [Google Fonts](https://github.com/google/fonts/tree/main/ofl/montserrat), лицензия SIL OFL находится рядом. Заголовок использует прежний DejaVu Sans (либо системный запасной шрифт). Без `--burn-captions` субтитры сохраняются отдельным файлом. При наличии подходящей фразы заголовок использует её как цитату, иначе формируется по шаблону. Цитаты стоит сверять с записью перед загрузкой.

## Поиск прямых эфиров Twitch

Зарегистрируйте приложение в [Twitch Developer Console](https://dev.twitch.tv/console/apps) и задайте `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET` в переменных окружения. После запуска скрипт получает токен приложения и выводит JSON со ссылками и текущим числом зрителей:

```bash
python3 twitch_live.py --language ru --limit 5
python3 twitch_live.py --channel "streamer1" --channel "streamer2" --limit 5
```

Можно изменить категорию через `--game "Grand Theft Auto V"` или `--game-id ID`. Команда возвращает снимок списка эфиров на момент запуска. Запись прямого эфира и публикация в аккаунты в этот пакет не входят.

## Развитие в автоматизированную систему

Проект требований к поиску авторов и перезаливов, монтажу, нескольким аккаунтам, публикации и личной аналитике находится в [SYSTEM_REQUIREMENTS.md](../SYSTEM_REQUIREMENTS.md). Личная панель в [control-room/](../control-room/README.md) ведёт источники, аккаунты и очередь. Python-сервис монтирует входящие файлы, пополняет очередь по языку и проверяет маршрут перед приватной отправкой YouTube после подключения OAuth. Для Reels и TikTok готовый MP4 доступен для ручной публикации. Подготовка аккаунтов и география аудитории описаны в [ACCOUNT_SETUP.md](../ACCOUNT_SETUP.md).

## Устройство проекта и ограничения

- `clips.py` проверяет исходник, ищет пики звука и движения либо принимает ручные отметки, запускает распознавание и экспортирует MP4, тексты и манифест. Результаты сначала создаются во временной папке; существующая папка экспорта не перезаписывается.
- `editing.py` рассчитывает области камеры и игры, кадрирование, порядок вставок `off` / `tease` / `move` и граф фильтров FFmpeg. Высота камеры на базовом холсте — 634 пикселя; центр оставшейся области — 1277 пикселей.
- `captions.py` читает SRT и слова из faster-whisper, переносит их на монтажную шкалу и создаёт SRT/ASS. Заголовок и речь имеют отдельные стили. Речь выровнена по горизонтальному центру и по умолчанию опущена на 72% высоты кадра.
- `twitch_live.py` получает список текущих эфиров через Twitch Helix. Он не записывает эфиры и не связан автоматически с монтажом.
- `assets/fonts/` содержит локальный Montserrat ExtraBold и лицензию. Статическое начертание получено из официального переменного Montserrat с весом 800; FontTools нужен только для подготовки шрифта, а не для запуска проекта.
- `preview_captions.py` воспроизводит образцы оформления; `test_captions.py` проверяет позицию, переносы, сохранение текста, подсветку, монтажные таймкоды и CLI.

Автоматический выбор моментов основан на громкости и изменении изображения: смысл диалога, качество шутки и события игры не анализируются. В раздельном макете исходная запись сканируется отдельно для игры, камеры и звука; длинные эфиры могут обрабатываться долго. Точность слов и подсветки зависит от распознавания. У SRT без словесных таймкодов деление времени приблизительное. Для переносов используется оценка ширины символов; произвольные эмодзи и редкие письменности могут потребовать запасной шрифт.

CLI готовит клипы, а отдельный сервис в `control-room/` ведёт очередь и пилот YouTube. Получение медиа по ссылке, запись эфиров и реальная отправка в Reels и TikTok пока требуют интеграций. Наличие FFmpeg/ffprobe в PATH обязательно; faster-whisper нужен только для `--transcribe`.

## Проверка и примеры оформления

```bash
python3 -m unittest -v
python3 preview_captions.py
```

Вторая команда обновляет только файлы примеров в `previews/`; другую папку можно задать через `--output`. Ролик примера длится 7,6 секунды, без звука: он демонстрирует оформление и смену подсветки на неподвижном кадре. Фразы и словесные таймкоды заданы вручную в скрипте.

При проверке изменений прошли 8 автоматических тестов и четыре полных экспорта на синтетическом видео: split 1080×1920 / tease / neon, split 720×1280 / move / gold, fit 720×1280 / clean и crop 720×1280 без аудио. Проверены декодирование MP4, размеры, длительность, наличие/отсутствие аудио, границы SRT, шрифт и манифест. Для этих проверок использованы временные локальные сборки FFmpeg/ffprobe, без установки в систему. Реальное распознавание faster-whisper и авторизованные запросы Twitch не запускались.
