# Аккаунты и маршрутизация Streamcut

Откройте [рабочую панель](http://127.0.0.1:8765/#accounts). Выберите площадку, нажмите «Добавить канал» и укажите название, направление RU/EN/ESP и ID канала или @имя. Карточка может быть сохранена до подключения API. Создавайте свои аккаунты через официальные интерфейсы, включите двухфакторную защиту и настройте восстановление доступа.

## YouTube

1. Создайте или выберите свой канал. Один Google аккаунт может управлять несколькими каналами Brand Accounts. Скопируйте ID канала, начинающийся с `UC`. [Создание канала](https://support.google.com/youtube/answer/1646861), [управление каналами](https://support.google.com/youtube/answer/4642409).
2. В Google Cloud включите YouTube Data API v3 и YouTube Analytics API. Создайте OAuth Client ID типа Desktop app, настройте экран согласия и при необходимости добавьте владельца как тестового пользователя. Укажите `STREAMCUT_GOOGLE_CLIENT_ID` и `STREAMCUT_GOOGLE_CLIENT_SECRET` только в окружении рабочего сервиса и перезапустите его. [Google OAuth для Desktop](https://developers.google.com/identity/protocols/oauth2/native-app), [YouTube Analytics](https://developers.google.com/youtube/analytics/reference/reports/query).
3. В карточке проверьте соединение, сохраните маршрут и нажмите «Подключить Google». На странице Google выберите нужный канал. Проверьте, что карточка подключилась. Не отправляйте секреты или OAuth коды в GitHub либо чат.
4. Для одного приватного теста включите `STREAMCUT_YOUTUBE_UPLOAD=1` в окружении сервиса, перезапустите его и подтвердите одно задание. После отправки сверьте ID и приватность в YouTube Studio. Автоотправка новых клипов отдельно включается на канал после проверки языка. [Про загрузку через YouTube Data API](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert).

## Instagram

Добавьте @имя в карточку Instagram. Для ручной публикации скачайте готовый MP4 из очереди и загрузите его из приложения. Для Insights переведите свой аккаунт в профессиональный Creator или Business. В Meta App Dashboard настройте Instagram Login, добавьте аккаунт в приложение и выдайте доступ с `instagram_business_basic` и `instagram_business_manage_insights`. Действующий токен передайте сервису как `STREAMCUT_INSTAGRAM_METRICS_<id>`, где `<id>` — номер карточки панели. Публикация через Meta API — отдельная интеграция. [Meta Insights](https://developers.facebook.com/documentation/instagram-platform/insights), [публикация Reels](https://developers.facebook.com/documentation/instagram-platform/content-publishing).

## TikTok

Добавьте своё @имя. Из очереди можно скачать MP4 и опубликовать его вручную. Если нужен общий счётчик подписчиков, настройте одобренный Login Kit / Display API и разрешения `user.info.profile`, `user.info.stats`. Действующий токен задаётся в окружении через `STREAMCUT_TIKTOK_METRICS_<id>`. Суточные просмотры и прирост этот адаптер не возвращает. TikTok прямо указывает, что личный инструмент публикации для своих аккаунтов не подходит для Direct Post. [Get User Info](https://developers.tiktok.com/docs/en/tiktok-api-v2-get-user-info), [правила Direct Post](https://developers.tiktok.com/docs/en/content-sharing-guidelines).

## Прямой маршрут и сервер

- **Прямой маршрут** — запросы поступают в API из обычной сети машины или контейнера, где запущен Streamcut. Это Mac при локальном запуске и VPS при запуске на VPS. Проверка показывает фактическую страну выхода без сравнения с заданной страной. Язык ролика и его местный часовой пояс от этого не меняются.
- **Россия / США / Испания** — именованные профили с проверкой ожидаемой страны. Они работают, только если владелец уже настроил подходящий доверенный HTTP CONNECT через приватную сеть или туннель. Для сервиса задаётся `STREAMCUT_PROXY_RU`, `STREAMCUT_PROXY_US` или `STREAMCUT_PROXY_ES`. Формат адреса доверенного локального шлюза `http://127.0.0.1:3128`. В Kubernetes адрес должен быть доступен из Pod. При ошибке или несоответствии страны отправка ждёт и чужой маршрут не подбирается.
- **Проверка** выполняется с рабочего хоста. Она подтверждает HTTPS-доступность и выход, а не права публикации. Сеанс OAuth в браузере и серверная отправка — разные соединения. Доступ к каналу YouTube дополнительно проверяется по ID перед фактической отправкой.
- **Порядок пилота.** Для одного личного сервиса начните с прямого маршрута на имеющемся VPS или на Mac. Сначала откройте «Подключения», проверьте каждую нужную площадку, затем авторизуйте один канал и проведите приватную проверку. Для круглосуточной работы нужен VPS с доступом к официальным API, устойчивой сетью и достаточным хранилищем для видео. Отдельный шлюз имеет смысл только при согласованном сетевом требовании. Покупка прокси для выбора аудитории не нужна. YouTube поясняет, что заданная страна канала не используется в рекомендациях. [Справка YouTube](https://support.google.com/youtube/answer/141805).

Для доступа к установленному сервису держите его на `127.0.0.1:8765` на VPS. На Mac откройте туннель, подставив своего пользователя и хост:

```sh
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:8765:127.0.0.1:8765 user@your-vps.example
```

Затем откройте [панель](http://127.0.0.1:8765/). Если на Mac уже запущен Streamcut на этом порту, остановите именно локальный экземпляр перед подключением. Выполняйте регистрацию и OAuth в обычном официальном браузерном потоке. SSH-туннель открывает доступ к панели на VPS, а запросы публикации по-прежнему идут из сети VPS. [OpenSSH](https://man.openbsd.org/ssh), [инструкция Kubernetes](control-room/deploy/README.md).
